# 07 · Key icon library and label text styling

**Done · 9 October 2026 · commits 52c85f5 (pushed) and 8aebd9b (unpushed) on master**

*Follow-up: reopening a saved key restarts the studio from defaults; see todo/16.*

**Priority:** P1 · **Effort:** M–L · **Hardware needed:** no for editor; yes to verify on keys

## Why
Official icon editor offers an icon library (30 per page, SVG/GIF), a "frequently used" tab, upload (≤800 KB), font, 4 text sizes, top/middle/bottom alignment and text/icon/background colours. Reviewers complain icons are not auto-fetched. Ours (`KeyArtworkEditor.tsx`, `ArtworkPage.tsx`) is upload/studio only.

## Scope
- Bundled icon set (e.g. Lucide + app glyphs; no CDN, per local-assets rule) with search and recents.
- Auto-suggest an icon from the assigned action (volume, mute, OBS scene, app icon for Open application using the .app icon).
- Text overlay controls: size (4 steps), alignment, text/icon/background colour.
- Live preview identical to what is sent to the key (shared renderer with `display_artwork.rs`).
- Fold the separate Display artwork page's key flow into the inspector; keep the page for bulk/offline prep.

## Acceptance
- Rendered preview matches the 72×72 JPEG sent to the key (pixel test).
- Works offline; no external font/CDN requests.

## What was done
- **Bundled icon library** (`src/key-icons.ts`, generated by `scripts/generate-key-icons.mjs`): 115 curated Lucide icons extracted from the installed `lucide-react` package's icon data (aliases like `trash-2` resolved), committed as source so the app builds and renders fully offline — no new runtime dependency, no CDN. Each entry carries id, display name and search keywords.
- **Icon picker in the inspector** (`KeyDesignStudio` in `KeyArtworkEditor.tsx`): a Suggested row, a collapsible Icon library with a search field (matches id/name/keywords), a Recently used row (localStorage `open-stream-hub.recent-key-icons`, newest first, capped at 8, junk-tolerant like the action picker's recents) and the full grid. Selecting an icon toggles it; the current one is accented.
- **Auto-suggestion** (`key-artwork-design.ts`): `suggestedIconIds` maps the bound action to fitting icons (volume/mute, media and system commands, OBS operations, URL/text/shortcut/multi-action/profile/timer). An Open application action offers the **real .app icon**: the new `app_icon` Tauri command resolves the bundle id through LaunchServices (`NSWorkspace`), decodes every representation in the icon's TIFF and PNG-encodes the one closest to the key's 72 px (`NSBitmapImageRep`), so asset-catalog icons work and a 1024 px source never crosses the wire. The chip loads once per bundle id (module cache), shows a spinner, and on failure disappears leaving the bundled app glyph suggestion.
- **Text overlay controls**: label text (with the key's current label as the starting point and the 128-byte label rules), four text sizes (Small 11 / Medium 14 / Large 18 / Extra large 24 px), top/middle/bottom alignment, and text/icon/background colour rows (hex text + picker each). Greedy word wrap with hard-break and ellipsis; 3/2/1 line caps by size.
- **Shared renderer**: designs draw on a 72×72 canvas (`keyDesignLayout` in the model, painted in `drawKeyDesign`) and are prepared through the existing `prepare_key_artwork` command with identity geometry (contain at exactly 72×72, quality 85), so the stored frames — the exact JPEGs the display feed sends — are what the preview shows after applying. While the user has not touched the studio, the design follows the assigned action and key label (ordinary edits do not remount the editor, so this is synced by effect, not mount state). Upload PNG/JPEG/GIF flow is unchanged below the studio.
- **Display artwork page**: kept for bulk/offline prep with both targets; its description now points single-key work to the workspace inspector ("To assign artwork to one key, use the Key artwork editor in the workspace inspector.").
- **Design note**: the design flattens into the existing `KeyArtwork` frames; the profile format is unchanged (`deny_unknown_fields` kept). Re-opening a saved key starts the studio from defaults rather than reverse-engineering the image.
