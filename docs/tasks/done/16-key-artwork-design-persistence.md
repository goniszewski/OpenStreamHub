# 16 · Persist the key artwork design

**Done · 10 October 2026 · commit 236e63c on master (pushed)**

**Priority:** P2 · **Effort:** M · **Hardware needed:** no

## Why
Task 07's icon-and-label studio flattens a design into the artwork's prepared JPEG frames, and the profile format has nowhere to keep the spec (`KeyArtwork` holds frames and loop count only, with `deny_unknown_fields`). Reopening a key therefore starts the studio from defaults, so a user who later tweaks an icon or colour must rebuild the design from scratch (flagged in the task 07 review).

## Scope
- Optional design metadata on `KeyArtwork` (crates/cooltek-sdk-service `key_artwork.rs` + `contracts.ts`): icon id (catalog id or `app:<bundle id>`), text, size, alignment, text/icon/background colours. `deny_unknown_fields` is kept for everything else; the new optional field must default to absent so old profiles parse unchanged.
- The studio initializes from the saved design when the key already has artwork; an icon id that no longer resolves (renamed catalog entry, unavailable app) degrades to the current defaults instead of erroring.
- Applying from an uploaded file clears the stored design.
- Keep the single prepare pipeline: the metadata never changes what is drawn, only what the studio reopens with.

## Acceptance
- Reopen a designed key and the studio shows its icon, text and colours without redoing them; applying again reproduces an equivalent image.
- Profiles without design metadata load, validate and render exactly as before (round-trip test in the service crate).

## What was done
- **`KeyArtworkDesign` on the wire** (`crates/cooltek-sdk-service/src/key_artwork.rs`, re-exported from the crate root; mirrored as `KeyArtworkDesignSpec` in `contracts.ts`): `icon_id` (optional, a catalog id or `app:<bundle id>`, omitted when absent), `text`, `text_size` (0–3), `align` (a closed `top`/`middle`/`bottom` enum), and `text_colour`/`icon_colour`/`background` hex as the studio types them. `KeyArtwork.design` is `#[serde(default, skip_serializing_if = "Option::is_none")]`, so profiles without a design parse **and serialize exactly as before**; `deny_unknown_fields` is kept on `KeyArtwork`, the design object, and everywhere else. The stored form is validated wherever artwork is (`KeyArtwork::validate` → `KeyArtworkDesign::validate`): icon id 1–128 bytes, text ≤ 128 bytes (the key label cap), both control-character-free, size 0–3, colours in the `#rgb`/`rgb`/`#rrggbb`/`rrggbb` shapes the studio's parser accepts. Malformed design metadata therefore refuses a profile at load like any other field; only icon-id *resolution* degrades in the UI (below), since the catalog is frontend knowledge.
- **Studio reopens with the saved design** (`KeyArtworkEditor`): the initial state comes from `keyDesignFromSpec(artwork.design, action)`, falling back to the action/label defaults when there is none. A restored design is sticky: until the user touches the studio it survives label and action edits (the editor does not remount for ordinary edits), and removing the artwork returns the studio to the fresh-key state. `applyDesign` stores `storedKeyArtworkDesign(design)` beside the prepared frames; the prepare pipeline, the request and the drawn pixels are untouched (identity geometry, quality 85 — unchanged from task 07).
- **Degrade, not error** (`keyDesignFromSpec` in `key-artwork-design.ts`): an icon id that no longer resolves — a renamed catalog entry, or an `app:` id whose bundle no longer matches the bound `launch_app` action — falls back to the same default suggestion a fresh studio would pick (none without a fitting action), while text, size, alignment and colours survive. Fields the stored form cannot shape (out-of-range size, unknown alignment, unparseable colour, oversized/control-character text) fall back to their defaults; a missing or absent design still returns null.
- **Uploads clear the design**: `prepare_key_artwork` answers uploads with design-less frames (`design: None` in the Tauri command and the CLI test helper), and `setKeyArtwork` replaces the whole artwork, so applying a file drops the stored design. No other flow changes; the CLI and live renderer read frames only.
- **Browser-preview QA hook**: dev-only `window.__oshKeyArtworkSeed(control, artwork)` in `App.tsx` (guarded by `!desktop && import.meta.env.DEV`, beside `__oshObsCatalogSeed`) so captures can exercise the reopen path, which the read-only preview cannot reach by applying.
- Docs synced: `apps/open-stream-hub/README.md` (Key artwork editor bullet) and `docs/masterhub-implementation-status.md`. Also parenthesised a pre-existing `clippy::precedence` warning in an artwork test pixel generator (introduced by the last commit before this task) so both workspaces stay clippy-clean.
