# 04 · OBS scene/source/filter pickers from obs-websocket

**In review · 9 October 2026 · commits 6a64ecd, 2abd417 and 0cf9cad on master (pushed)**

## Why
Official app fills scene, source, filter, collection, profile dropdowns from OBS ("No Data" when empty). We make the user type names; typos fail silently at press time.

## Scope
- Service/Tauri command to list scenes, sources, filters, scene collections, profiles over the existing loopback obs-websocket connection.
- Editor fields become comboboxes: pick from list, still allow typing when OBS is offline.
- Refresh button, empty state ("Start OBS and enable WebSocket"), and inline validation when the saved name is not found.
- Password remains memory-only (see Keychain item in parity tracker).

## What was done

**Backend.**
- `ObsClient::catalog` in `crates/cooltek-sdk-service/src/obs.rs`: one connection, four requests (`GetSceneList`, `GetInputList`, `GetSceneCollectionList`, `GetProfileList`), one 3 s deadline; returns `ObsCatalog { scenes, sources, scene_collections, profiles }`. `ObsClient::source_filters` (`GetSourceFilterList`, a scene name works too) and `ObsClient::scene_sources` (`GetSceneItemList` — what a source visibility in that scene can target) fetch the per-name lists. Reply shapes follow the obs-websocket v5 protocol exactly (checked against `docs/generated/protocol.md`): scenes, inputs, filters and scene items are object arrays (`sceneName`, `inputName`, `filterName`, `sourceName`); scene collections and profiles are bare string arrays (`listed_names` takes `name_key: Option<&str>`). An earlier draft of the fake server had collections and profiles as object arrays, which real OBS would have rejected — fixed, with the spec shapes asserted in the fake-server tests. Replies are bounded: at most 1000 entries per list (`MAX_LISTED_NAMES`), and names beyond the profile's own 128-byte name limit (`MAX_LISTED_NAME_BYTES = Action::MAX_OBS_NAME_BYTES`) are dropped, so one long name never fails a list and every offered name is savable (the frontend mirrors the same limit); a malformed entry (missing or non-string name) is an error, never a silently partial list. Names travel only as JSON string values; a refused listing reports the reason without echoing the name.
- Three Tauri commands (`obs_catalog`, `obs_source_filters`, `obs_scene_sources` in `src-tauri/src/lib.rs`), registered in `generate_handler!`, `build.rs` and `capabilities/main.json`. `ObsState::for_listing` (src-tauri `obs.rs`) supplies the saved endpoint and the in-memory password and refuses while OBS is off in Settings ("OBS is off in OpenStreamHub Settings") — the empty state the editor shows; a connect failure surfaces OBS's own "is OBS running with its WebSocket server on?" wording. Password handling unchanged: memory only, stdin pipe to the service.
- Shared IPC fixture `fixtures/obs-catalog.json` generated by `contract_fixtures.rs` (verified shapes for the three replies and their name arguments).

**Frontend.**
- New `obs-catalog.ts`: `ObsCatalogStore` (fetch/sort/dedupe, per-name list cache fetched on demand from the field's open event, failure reasons kept per list, `seedPreview` for QA) and `useObsCatalog` (asks once per app session on mount). Threaded App → Inspector and App → ProfilesPage → DialFunctionsPanel → ActionFields → ObsFields/ObsConnection; without a store the fields stay exactly what they were.
- `ObsCombo` (hook-free, controlled — same technique as the action picker) + `ObsNameField` inside `ActionFields.tsx`: click or ArrowDown opens the choices, typing narrows case-insensitively, Enter/click picks the exact name, Escape/outside press closes; full ARIA combobox wiring (`aria-expanded`, listbox options, `aria-activedescendant`). Typing always works; names a profile cannot save (over 128 bytes) are never offered; more than 50 matches end with "N more — keep typing to narrow the list."; the popup says "Looking up OBS…" while fetching and shows the failure text when a listing fails.
- Inline cross-check: when the loaded list does not contain the exact saved name, the field shows "OBS does not list this scene right now. Refresh the OBS lists, or check the exact spelling." (role=note; name-rule errors keep precedence and role=alert). A filter's source choices are OBS's inputs and scenes together; a visibility's source choices are the items of its named scene.
- One **Refresh from OBS** row per editor in `ObsConnection` (label "Listing…" while loading, press disabled then; the failure reason is shown next to it). Browser preview without data renders unchanged, so the earlier OBS captures stayed valid.
- Styles: `.combo-list`/`.combo-note`/`.obs-name`/`.field-warning`/`.obs-catalog` in `styles.css`.
